PeopleSoft Trace Settings & Diagnostics Quick Reference

Use the smallest trace that answers the question. Trace settings are additive bitmasks. SQL and PeopleCode tracing can add overhead and trace files can contain sensitive values.

Oracle: Configuring SQL Trace  |  Oracle: Configuring PeopleCode Trace  |  Oracle: Trace Section

Recommended trace recipes
Slow online page / SQL performance
TraceSQL=3
SQL statements (1) + bind variables (2). Oracle documents 3 as the typical essential SQL trace. Add 4 when commit/rollback/connect context is needed.
SQL fetch / transaction behavior
TraceSQL=7 or 15
7 adds connect/disconnect/commit/rollback. Add 8 for fetch events when row-fetch behavior matters. Higher levels increase volume.
PeopleCode execution flow
TracePC=1
Traces the program as it runs and implies program-start, external-function, and internal-function tracing. Use for event-flow and loop investigations.
PeopleCode variable/value issue
TracePC=1+4+8
Execution plus assignments and fetched values. Add 512+1024 when parameter flow matters. Use only for a targeted reproduction.
AE step / control-flow problem
TraceAE=1+2
Step sequence plus Application Engine SQL. Use when a section/step/action executes unexpectedly or you need SQL-to-step context.
AE performance
TraceAE=128; add 256
128 produces statement timings. 256 adds method/built-in detail. Add 2 when SQL attribution is needed.
AE temporary-table issue
TraceAE=4; add 8
4 traces dedicated temp-table allocation. 8 traces temp-table data and is higher volume; use it when row-level effects are important.
AE execution plan
TraceAE=2048 or 4096
Optimizer trace to file or tables, subject to RDBMS/platform support. Use when timing evidence identifies a SQL plan problem.
Integration Broker transform
TraceAE=8192
Use for transform-program problems. Oracle documents transform trace output for the original XML and transformed output.
Long-term AE SQL timing history
TraceAE=16384
SQL timings stored in PS_AE_TIMINGS_LG and PS_AE_TIMINGS_DT where supported by the PeopleTools interface/release.

Interpretation rules used by Trace Insights
Heuristics are not proof. A repeated SQL fingerprint is a candidate N+1 pattern, not proof of N+1. A statement without WHERE is an unconstrained-SQL review signal, not proof of a full table scan. A slow statement without optimizer evidence does not prove a bad execution plan.

For a defensible root-cause conclusion, prefer correlated evidence: error → SQL → bind → PeopleCode/AE step → surrounding trace context. The analyzer shows confidence and should distinguish confirmed evidence from review candidates.

Tracing can materially affect performance. Use the minimum trace needed, reproduce narrowly, and turn tracing off after collection. Trace files can contain SQL bind values and PeopleCode values and should be handled as sensitive diagnostic artifacts.

1. Tool Overview & Architectural Concept

PeopleSoft Trace Insights (Browser Edition) is an enterprise diagnostic platform packaged into a self-contained, single-file HTML application. It operates 100% client-side directly within the web browser using modern Web APIs (FileReader, TypedArray, Performance, Int32Array).

2. Complete User Interface (UI) Architecture
Top Navigation Header (#hdr)
Houses branding, real-time V8 heap memory monitor (performance.memory), and instant actions: Home, Compare Traces, CSV Export, Theme Toggle (Dark/Light), Help, and Read me.
Landing & Drag-and-Drop Zone (#dz)
Zero-upload ingestion target with drag-and-drop listener, native file browser, and progress bar scaling from 0% to 100% across reading and parsing phases.
Executive Overview & RCA Dashboard
Presents computed Trace Health score (0-100), automated Root Cause Analysis & remediation cards, synthesized findings, and system metadata profiles.
Interactive SQL Statements Data Grid
Searchable, multi-column sortable table with subtabs: All, Slow, Errors, Repeated Patterns (N+1), High Fetch, By Where, By From, and Tables (By Type).
Execution Call Tree Workspace (#p-exec)
Hierarchical tree view mapping PeopleCode events, App Engine steps, and SQL statements with duration metrics, error node highlights, and inline code previews.
Execution Path Compare Page (#comparePage)
Side-by-side diff algorithm visualizer highlighting execution divergence points, last synchronous steps, and bind/variable differences between two traces.
3. How to Use the Tool (8-Phase Workflow)
Phase 1: Ingesting Traces
Open the single HTML file in any browser and drag your .tracesql, .trc, or .aet file onto the drop card. Processing is 100% client-side with safe memory limits.
Phase 2: Reviewing Health & Root Cause Analysis
Check the Trace Health Score (80-100: Healthy; 55-79: Warnings; 0-54: Critical). Review the Root Cause Analysis & Remediation card to read prescribed fixes and launch associated trace evidence.
Phase 3: Investigating SQL Bottlenecks & N+1 Loops
Navigate to the SQL Statements tab. Filter by Slow (dur >= 1.0s) or Repeated Patterns to evaluate N+1 confidence scores. Click any row to view and copy substituted SQL with bind parameters inlined.
Phase 4: Exploring the Execution Call Tree
Open the Execution Path tab to trace execution hierarchies. Expand all or collapse nodes, isolate red-highlighted error nodes, and view inline PeopleCode statement previews.
Phase 5: Diagnosing Exceptions & Value Anomalies
Switch to Diagnostics & Issues to inspect unhandled exception stack traces, uninitialized variables, null buffer fetches, empty fetches, and component buffer deserializations.
Phase 6: Tracing Variable Flow & Binds
In Variable Flow, search for any variable (e.g. &EMPLID) to inspect its chronological lifecycle (FETCH, STORE, ASSIGN). Click View correlated SQL to jump directly to statements using that value.
Phase 7: Running Comparative Execution Diffs
Click Compare Traces in the header. Select a Baseline trace and Target trace, then run path compare. Inspect the exact step where logic diverged and examine side-by-side bind/variable mutations.
Phase 8: Exporting Diagnostic Telemetry
Click CSV in the header to download trace_insights_diagnostics.csv containing SQL metrics, fingerprints, error classifications, and bind mappings for spreadsheet reporting.
